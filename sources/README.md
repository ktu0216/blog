# sources/ — 블로그 작성용 원본 자료

블로그 글의 **출발 자료**(사내에서 진행한 자료, 외부에서 가져온 참고자료)를 여기에 둔다.

## 규칙 (중요)
- **이 폴더 내용은 git에 커밋되지 않는다** (`.gitignore`: `sources/*`, README·PROMPT·TEMPLATE만 추적).
  블로그는 **공개 레포(GitHub Pages)** 라, 원본 자료가 커밋되면 그대로 노출된다.
- 글로 완성할 때는 `CONTENT-RULES.md`에 따라 **PII·내부정보를 더미로 치환**한 뒤
  `src/content/posts/`에 작성한다. 원본은 여기 남고, 공개본만 나간다.

## 어디에 무엇을 두나
- **작업용/치환 가능한 자료** → 여기 `sources/<YYYY-MM>_<슬러그>/` (편의상 레포 안, 단 ignore됨)
- **민감한 내부 문서**(실계정·비밀·미공개 재무 등) → 레포 밖 **`~/code/ktu-docs`** 에 보관.
  gitignore는 실수 방지용일 뿐, 진짜 민감정보는 애초에 레포 트리에 두지 않는 게 안전.

## 폴더 구조

```
sources/
├── README.md                        이 파일 (추적됨)
├── PROMPT.md                        업무 PC에서 쓰는 변환 프롬프트 (추적됨)
├── TEMPLATE.md                      소스 문서 서식 (추적됨)
├── 2026-08_github-ent-migration/    ← 작업 시점 + 슬러그
│   ├── source.md                    TEMPLATE을 채운 본문
│   └── …                            부속 자료(있으면)
└── on_call/                         (구 형식 — 다음에 이 폴더로 일할 때 개명)
```

- 날짜는 **작업 시점**(반출한 날이 아니라). 여러 달에 걸쳤으면 시작 월을 쓴다.
- `YYYY-MM-DD`가 아니라 `YYYY-MM`인 이유 — 업무는 대개 며칠 이상 걸려서 하루 단위는 거짓 정밀도다.
- 폴더가 20개를 넘으면 그때 `sources/<YYYY>/` 를 한 겹 넣는다. 그전엔 넣지 않는다.

## 업무 자료를 소스로 만드는 절차

1. **업무 PC**에서 `PROMPT.md`의 프롬프트 블록을 복사해 AI 어시스턴트에 붙여넣고 대상 자료를 준다.
   (AI를 쓸 수 없으면 그 프롬프트를 질문지 삼아 직접 답한다.)
2. 출력된 마크다운 **한 장만** 개인 쪽으로 옮긴다. 원본 파일은 옮기지 않는다.
3. `sources/<YYYY-MM>_<슬러그>/source.md` 로 저장한다.
4. `<확인: …>` 표시를 직접 판단해 정리하고, **반출 점검 7줄을 눈으로 다시 본다.**
5. `disclosure: 하` 면 소재로 쓰지 않는다. 기록은 남겨둔다.
6. 쓸 만하면 `anchors`를 `topics-pool.md`에 옮겨 적는다.

> 옮기는 것은 **파일이 아니라 이미 익명화된 메모**다. 사내 산출물을 그대로 가져오면
> 발행할 때마다 지울 것이 생기고, `CONTENT-RULES.md`가 금지하는 "실제값 넣고 나중에 지우기"가 된다.

## 파이프라인 연계
ideator(앵커=실제 작업)·researcher가 이 자료를 참고 소스로 쓸 수 있다.
글감 확정 후 `output/<날짜>_<슬러그>/`에서 리서치→초안이 진행된다.
