# 업무 자료 → 블로그 소스 변환 프롬프트

업무 PC에서 사용한다. 아래 블록을 그대로 복사해 AI 어시스턴트에 붙여넣고, 뒤에 대상 자료를
붙이거나 파일 경로를 알려준다. **출력된 마크다운 한 장만** 개인 쪽으로 옮긴다.

> AI 도구를 쓸 수 없는 환경이면 이 프롬프트를 **혼자 답하는 질문지**로 써도 된다.
> 항목 순서가 그대로 회고 순서다.

---

## 붙여넣을 프롬프트

```text
너는 내 업무 기록을 공개 기술 블로그의 "소스 문서"로 바꾸는 역할이다.
결과물은 내가 개인 PC로 옮겨 블로그 글의 재료로 쓴다.

## 가장 중요한 규칙
출력물에는 회사를 식별할 수 있는 정보가 처음부터 들어가면 안 된다.
"일단 쓰고 나중에 지운다"는 금지다. 지운 흔적도 남기지 않는다.

다음은 절대 출력하지 않는다.
- 사내 시스템·서비스·프로젝트·제품의 실제 이름
- 회사명·부서명·팀명·사람 이름·직함
- 사내 도메인·호스트명·서버명·IP·포트·계정·URL
- 고객사·거래처·협력사 식별 정보
- 미공개 재무 수치(매출·비용 절대액·계약 규모·인건비)
- 사내 문서의 문장을 그대로 옮긴 것 (반드시 다시 쓴 문장으로)

대신 이렇게 바꾼다.
| 실제 | 출력 |
|---|---|
| 사내 위키/그룹웨어 이름 | "사내 위키", "그룹웨어" |
| 사내 시스템 이름 | 역할로 서술 — "사내 인증 시스템", "배포 도구" |
| 회사·팀 이름 | "회사", "팀" |
| 도메인·호스트 | example.com, example-host |
| IP | 10.0.0.x |
| 계정·키 | <YOUR_KEY>, user@example.com |
| 경로 | /home/<user>/... |
| 금액·매출 | 상대값으로 — "절반으로", "3배" |

판단이 서지 않는 항목은 지우지 말고 `<확인: 무엇>` 으로 표시해 남긴다.
내가 나중에 직접 판단한다.

## 무엇을 뽑을 것인가
블로그 글에 필요한 것은 산출물이 아니라 **판단의 흐름**이다. 우선순위 순으로:

1. 예상과 달랐던 지점 — 막혔던 곳, 착각했던 것, 원인을 찾기까지의 과정
2. 선택의 근거 — A 대신 B를 고른 이유, 검토했지만 버린 선택지
3. 되돌린 결정 — 도입했다가 걷어낸 것, 틀렸던 판단
4. 일반화 가능한 구조·절차 — 다른 조직에서도 성립하는 형태
5. 결과와 남은 숙제

반대로 이런 것은 넣지 않는다.
- 회사 사정·조직 맥락·의사결정 정치
- 일정·공수·담당자 배분
- "성공적으로 마무리했다" 류의 요약 문장

막혔던 지점이 하나도 없으면 그렇게 적는다. 없는 것을 만들지 않는다.

## 공개도 판정
마지막에 disclosure를 상/중/하 중 하나로 정하고 한 줄 근거를 단다.
- 상 — 등장하는 기술이 전부 공개 도구고, 회사 맥락을 걷어내도 내용이 성립한다
- 중 — 구조·절차는 일반적이나 사내 명칭·구성이 섞여 있어 치환이 필요하다
- 하 — 사내 전용 시스템이나 고객 데이터가 핵심이라, 치환해도 식별될 수 있다

## 출력 형식
아래 형식의 마크다운 **한 장만** 출력한다. 설명·인사말·요약을 앞뒤에 붙이지 않는다.
빈 항목은 "없음"으로 채우고 임의로 지어내지 않는다.

---
slug: <영문-케밥-슬러그>
title_hint: <한글 한 줄>
period: <YYYY-MM 또는 YYYY-MM ~ YYYY-MM>
written: <오늘 날짜 YYYY-MM-DD>
disclosure: <상 | 중 | 하>
anchors: [<앵커 후보>, <앵커 후보>]
lens_hint: <되돌린 결정 | 문제 해결 기록 | 도구 선택 기준 | 구조·규칙 공개 | 없음>
confidence: <자료 확인 | 기억 기반>
---

## 한 줄
## 배경 — 왜 했나
## 한 일
## 막힌 지점
(예상 / 실제 / 원인 순으로, 여러 개면 여러 개)
## 결정과 근거
(선택지 비교표)
## 되돌린 것 / 버린 것
## 결과
## 숫자
(상대값만)
## 재현 조각

## 확인 필요
## 반출 점검
(아래 7개를 체크리스트로 그대로 출력하되, 스스로 검증한 뒤 [x] 표시)
- [ ] 사내 시스템·서비스·프로젝트 실명 없음
- [ ] 조직·부서·사람 이름 없음
- [ ] 사내 도메인·호스트명·IP·계정 없음
- [ ] 고객사·거래처 식별 정보 없음
- [ ] 미공개 재무·계약 수치 없음
- [ ] 사내 문서를 그대로 옮긴 문단 없음
- [ ] 스크린샷·로그 첨부 없음

## 대상 자료
아래가 변환할 업무 자료다.
```

## 옮긴 뒤 할 일

1. `sources/<YYYY-MM>_<슬러그>/source.md` 로 저장한다.
2. **`<확인: …>` 표시를 직접 판단해 지운다.** AI가 애매하다고 남긴 것들이다.
3. 반출 점검 7줄을 눈으로 다시 본다. AI 체크를 믿지 않는다.
4. `disclosure: 하` 면 블로그 소재로 쓰지 않는다. 그래도 기록은 남겨둔다.
5. 쓸 만하면 `anchors`를 `topics-pool.md`에 옮겨 적는다.
