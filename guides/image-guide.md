# 블로그 이미지 가이드 (image-maker용)

> image-maker 에이전트가 읽는 **이미지 제작 가이드**. `draft.md`의 `[IMAGE: 설명]` 마커를
> 이 규칙에 따라 실제 이미지로 만든다(대표 이미지는 SVG). 이미지는 **본문을 돕는 보조 수단** — 텍스트는 짧게.

---

## 0. 색 팔레트 (공통 토큰 — 모든 이미지가 공유)
모든 이미지(썸네일·본문 4종)는 **하나의 브랜드 팔레트**를 공유한다. 강조색은 **사이트 강조색과 동일한 파랑 계열**(라이트 `#006cac` / 다크 `#4aa3df`)이며, 초록·주황 등 다른 강조색을 섞지 않는다. 각 HTML `<head>`에 아래 `:root`를 넣고 색은 **변수로만** 참조한다.

```css
:root{
  --img-bg:#0a1020;       /* 썸네일 그라데 시작(딥 네이비) */
  --img-bg2:#006cac;      /* 썸네일 그라데 끝(브랜드 파랑) */
  --img-panel:#0d1117;    /* 본문 도형 카드 배경(다크) */
  --img-surface:#161b22;  /* 노드/패널 배경 */
  --img-fg:#e6edf3;       /* 밝은 글자 */
  --img-muted:#8b949e;    /* 보조 글자 */
  --img-accent:#4aa3df;   /* 강조 1개만(브랜드 파랑, 다크 위 대비) */
  --img-border:#30363d;
}
```
- **색 역할은 3개로 제한**: 배경 / 글자 / **강조 1개**(+무채색 보조). 강조색은 화면의 ~10% 이하, "강조"에만.
- 강조색 변경 시 이 토큰만 바꾸면 **전 이미지가 일괄로** 바뀐다.

## 1. 대표(썸네일) 이미지 — 글에서 뽑아낸다

### 왜 제목을 넣지 않나
이 이미지가 노출되는 곳은 **본문 도입부 아래 한 곳뿐**이다. H1 제목 바로 밑이다.
- 공유용 OG 이미지는 이것이 아니다 — `src/pages/posts/[...slug]/index.png.ts` 가 따로 자동 생성한다.
- 글 목록에는 이미지가 나오지 않는다.

즉 제목을 그려 넣으면 200px 위의 제목을 한 번 더 반복하는 것이고, 그 자리에 담기는 정보는 0이다.
**대표 이미지에는 글이 실제로 가진 것을 담는다.**

### 공통 규격 (형식과 무관하게 항상)
- **크기**: 1080 × 1080 (1:1). **형식**: SVG를 손으로 작성.
- **배경**: `--img-panel`(`#0d1117`) 단색. **그라데이션 배경 금지.**
- **좌측 강조 바**: 폭 8px, 세로 전체, `--img-accent`.
- **상단 라벨**: 좌상단에 모노스페이스 한 줄(자간 넓게, `--img-muted`). 무엇을 보여주는 화면인지 알리는 3~8자.
- **정렬**: **좌측 정렬.** 중앙 정렬 금지 — 데이터 카드로 읽혀야 한다.
- **우하단 마크**: `[ >_ ]`, `--img-accent`, opacity 0.7.
- **강조색은 하나**(`--img-accent`). 화면의 10% 이하, 이 이미지가 말하려는 것 딱 하나에만.
- 하단 2줄로 마무리: 굵은 한 줄(결론) + 옅은 한 줄(단서·조건).

### 형식 4종 — 위에서부터 물어보고 처음 걸리는 것을 쓴다

**A · 수치형** — 글에 **측정한 전/후 숫자**가 있는가
> 전 값을 작고 옅게, 후 값을 크고 강조색으로. 사이에 가는 구분선.
> 하단에 **그 숫자를 스스로 깎는 단서**를 반드시 붙인다(예: "그중 2초는 배포판 기본값 — 실질 1.4초").
> 숫자만 크게 띄우고 끝내면 과장이 된다.

**B · 증거형** — 이야기의 중심이 된 **에러·명령·출력 한 줄**이 있는가
> 터미널 패널(`--img-surface` + `--img-border`, 라운드 14) 안에 실제 출력을 모노스페이스로.
> 결정적인 토큰 하나만 `--img-accent` + 밑줄. 나머지는 `--img-muted`.
> 패널 상단에 출처 경로 한 줄(`/var/log/secure` 등).

**C · 선택형** — **선택지를 놓고 하나를 고른** 글인가
> 소스의 `## 결정과 근거` 표에서 그대로 뽑는다. 기각안 2개 + 채택안 1개.
> 기각안은 `--img-muted` + 취소선, 각 행에 **기각 이유 한 줄**.
> 채택안만 `--img-accent` 테두리와 "채택" 칩.
> **기각 이유를 빼지 않는다** — 이 형식의 값어치가 거기 있다.

**D · 도식형** — **구조나 관계를 설명하는** 글인가
> 글의 핵심 논지를 노드와 선으로. 본문 도식을 그대로 축소하지 말고, **논지 한 개만** 남긴다.
> 연결되지 않는 것·끊긴 것은 점선과 `✕`로 명시한다.

**넷 다 아니면 대표 이미지를 만들지 않는다.** 빈 카드를 넣는 것보다 없는 편이 낫다.

### 금지
- 글 제목을 그대로 옮겨 적기
- 그라데이션 배경, 중앙 정렬, 배지 + 제목 + 부제 조합
- 형식을 미리 정해두고 글을 거기 맞추기 — 순서대로 물어보고 걸리는 것을 쓴다

## 2. 본문 삽입 이미지 — 4종 중 글 내용에 맞게 선택
1. **비교 표** — 제품/방법을 나란히 비교할 때.
2. **단계별 다이어그램** — 절차·순서를 보여줄 때.
3. **핵심 포인트 카드** — 3~5개 요점을 정리할 때.
4. **인용/강조 박스** — 중요한 한 마디를 강조할 때.

> `[IMAGE: …]` 마커의 설명을 보고 위 4종 중 가장 맞는 형식을 고른다.
> 예: `[IMAGE: … 비교 표]` → 1번, `[IMAGE: … 단계별 다이어그램]` → 2번.
- **권장 크기**(본문): 가로 **1200px**, 높이는 내용에 맞게(가변). 대표 이미지와 **색감·톤을 통일**.

## 3. 공통 규칙
- **제작 방식**: **대표 이미지는 §1대로 SVG를 직접 작성**한다(텍스트가 벡터로 남고 파일이 작다).
  본문 이미지는 SVG로 만들거나, 레이아웃이 복잡하면 HTML + CSS로 만들어 **Python + Playwright**로 PNG 캡쳐한다.
  어느 쪽이든 **렌더해서 눈으로 확인**한다 — 글자 겹침과 카드 경계 넘침이 가장 흔한 결함이다.
  ```python
  from playwright.sync_api import sync_playwright
  with sync_playwright() as p:
      b = p.chromium.launch()
      pg = b.new_page(viewport={"width": 1080, "height": 1080}, device_scale_factor=2)
      pg.goto("file:///abs/path/to/thumb.html")
      pg.screenshot(path="output/<날짜>_<슬러그>/images/thumb.png")  # 요소만: locator.screenshot()
      b.close()
  ```
  - 본문 이미지는 viewport 폭 1200, 높이는 콘텐츠에 맞춰 `full_page=True` 또는 해당 요소만 캡쳐.
  - 선명도를 위해 `device_scale_factor=2`(2배 해상도) 권장.
- **배경 톤**: §0 토큰(`--img-panel`/`--img-surface`)으로 **어두운 톤 통일**. 강조는 `--img-accent` 하나만.
- **텍스트는 최대한 짧게** — 이미지는 보조. 문장 나열 금지, 키워드·요점 위주.
- **코드 블록 스타일을 디자인 요소로** 활용 가능(모노스페이스 폰트, 어두운 배경, 살짝 둥근 모서리).

## 4. 산출·연결
- **저장 위치**: `output/<날짜>_<슬러그>/images/` (예: `thumbnail.svg`, `body-1.svg`).
- **파일명**: 대표 이미지는 `thumbnail.svg`, 본문 이미지는 `body-1`, `body-2` … 순번.
- **alt/캡션**: `../guides/seo-guide.md`의 이미지 규칙을 따른다(설명+키워드 자연 포함, 과도한 키워드 X).
- 다음 단계 **assembler**가 `draft.md`의 `[IMAGE: …]` 마커를 이 이미지들로 교체해 최종본을 만든다.
